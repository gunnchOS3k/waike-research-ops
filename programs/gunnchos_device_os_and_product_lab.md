# gunnchOS Device OS and Product Lab

**Track ID:** `GUNNCHOS_PRODUCT_LAB`  
**Academy:** ACADEMY_HARDWARE  
**Extension class:** ADVANCED_EXTENSION

## Purpose / audience
Apprentices who will ship product-facing Device OS experiences: requirements → architecture → integration with hardware/industrial design → test → release → portfolio. Not a substitute for physical EVT bring-up evidence.

## Prerequisites
- SOFTWARE_BUILDER or equivalent git/API discipline
- HARDWARE_ENGINEERING fundamentals recommended
- Read `docs/LIMITATIONS_AND_NON_CLAIMS.md`

## Learning outcomes
1. Write testable user stories and non-functional requirements for a Device OS surface.
2. Map system architecture across apps, services, and capability adapters without inventing unmerged hardware.
3. Exercise digital Device Lab / simulator paths before any PHYSICAL_PENDING step.
4. Apply accessibility, privacy, and security review checklists to a release candidate.
5. Produce a portfolio packet with provenance, claim boundary, and reproducibility notes.

## Module sequence (10 weeks)
1. Product problem framing and stakeholder map  
2. User stories and acceptance criteria  
3. System architecture and capability adapters  
4. Hardware/software interface contracts (digital fixtures)  
5. Device OS integration paths (local Device Lab)  
6. Testing strategy (unit, contract, smoke)  
7. Accessibility and inclusive interaction  
8. Security/privacy review and threat notes  
9. Release engineering, telemetry, rollback  
10. Capstone portfolio + claim boundary defense  

## Assessment doctrine
Exam weight stays within WAIKE `exam_weight_max`. Portfolio + practical labs dominate. HITL grading required for educator publish.

## Claim boundary
No accreditation, no employment guarantee, no fabricated field trial, no claim that unmerged Device OS PRs are shipping product.
